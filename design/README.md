# Good Measure — Design standards v0.1

## 브랜드 문구

Good ideas. Better made. / 충분히 생각하고, 제대로 만듭니다.

핵심 태도: 분명한 목적 → 근거 있는 선택 → 정확한 구현. 과장된 규모나 성과 대신 판단과 완성도를 이야기합니다. Hummman의 명칭·슬로건·연락처를 새 브랜드 소개에 사용하지 않습니다. 기존 공개 사례는 참고 프로젝트로 명시하며 새 브랜드의 수주 실적으로 주장하지 않습니다.

## 원본과 제안 구분

- `source-audit.json`: 기존 로컬 프로젝트의 CSS/SCSS를 읽어 수집한 실제 선언값. 파일·행 근거를 포함합니다. 주석과 SCSS 옆의 컴파일 CSS는 제외합니다. 레이아웃 계산값이나 디자인 의도의 증거는 아닙니다.
- `tokens.json`: 관찰한 패턴과 이번 시안에 맞춰 정리한 **새 제안값**입니다. 기존 프로젝트에 이미 적용되어 있었다고 주장하지 않습니다.
- Figma: BeyondC 1개 페이지와 IDhair 2개 페이지의 실제 텍스트 스타일·Auto Layout·그리드를 읽기 전용으로 분석했습니다. figma-audit.json과 FIGMA_FINDINGS.md에 원본값·노드 근거·판단을 기록했습니다.

## 사용법

`tokens.json`이 기준 원본입니다. 값을 바꾸고 `npm run design:tokens`로 CSS를 생성합니다. 페이지에서 `design-tokens.css`를 먼저 불러오고 컴포넌트에서 의미별 변수를 사용합니다.

| 항목 | 기준 |
| --- | --- |
| 간격 | 4, 8, 12, 16, 20, 24, 32, 40, 48, 60, 64, 80, 96, 120, 128, 160px |
| 반복 컴포넌트 내부 | 8 / 12 / 16 / 24px |
| 컴포넌트 간 | 24 / 32 / 48px |
| 섹션 간 | 60~120px 유동값 |
| 본문 | 16px / 행간 1.75, 읽기 너비 최대 65ch |
| 보조 설명 | 14px / 1.5 이상 |
| 캡션·메타 | 12px 이상, 핵심 정보를 작은 캡션에만 넣지 않음 |
| 카드 제목 | 24px |
| 섹션 제목 | 40~60px 유동값, 행간 1.08 |
| 대형 히어로 | 48~160px 유동값(모바일의 긴 문구는40~60px), 행간 1.0 |
| 버튼 | 최소 터치 높이 44px, 14px 텍스트 |
| 콘텐츠 그리드 | 모든 화면 구조12열, 카드 배치는 모바일12열/태블릿·데스크톱6열 |
| 반응형 | 0~599 / 600~1023 / 1024px 이상 |

그리드 열 수는 화면 구성 기준입니다. 현재 시안의 프로젝트 목록은 모바일 1개, 태블릿·데스크톱 2개씩 배치합니다. 강한 비대칭 오프셋은 데스크톱에서만 사용합니다.

### 예외

1px 테두리, 로고의 광학 보정, SVG 내부 좌표, 회전 그래픽 크기·위치, 고정 비율 미디어는 간격 단위 강제 대상이 아닙니다. 새로운 예외는 이유를 남기고 재사용되면 토큰으로 승격합니다. 모든 픽셀을 동일하게 만드는 것이 아니라 반복되는 판단을 같게 만드는 기준입니다.

## Figma 매핑 계획

| Figma | 코드 |
| --- | --- |
| Variables: space/4, space/8, space/12… | --space-1, --space-2, --space-3… |
| Variables: color/paper, color/ink, color/accent | --color-paper, --color-ink, --color-accent |
| Text styles: Body/Default, Body/Small, Label, Title/Card | --font-body, --font-small, --font-caption, --font-card |
| Text styles: Heading/Section, Display/Hero | 반응형 최소·최대값과 기준 프레임의 실제 크기를 함께 기록 |
| Auto Layout: padding / itemSpacing | 해당 space 토큰 |
| Layout Grid: columns / gutter / margin | 12열 / 별도 컴포넌트 grid-gap / page-gutter |

제공된 두 파일의 대표 데스크톱·모바일 프레임과 텍스트 스타일, Auto Layout을 조사하고 반복값·예외를 비교했습니다. 프로젝트별 개성을 공통 토큰에 억지로 맞추지 않고 기초 규칙과 프로젝트별 표현을 구분합니다. 사용자 요청 없이 원본 Figma 파일이나 기존 프로젝트를 수정하지 않습니다.

## 반복 작업 절차

1. 기존 코드·Figma를 읽기 전용으로 조사하고 원본값 및 근거를 기록합니다.
2. 같은 역할의 근접값을 묶습니다. 빈도만으로 좋은 값이라 판단하지 않습니다.
3. 원시값(16px) → 의미(본문) → 컴포넌트(카드 설명) 순서로 연결합니다.
4. 토큰 변경은 이 페이지와 대표 컴포넌트에서 먼저 확인합니다.
5. 390 / 768 / 1440px 기준으로 줄바꿈·가로 넘침·터치 영역·대비를 확인합니다.
6. Figma 변수와 코드 토큰을 같은 이름으로 유지하고 변경 이유를 기록합니다.

조사 재실행: `npm run design:audit`. 다른 프로젝트 경로를 인자로 전달할 수도 있습니다. 읽기 전용 조사 결과만 현재 프로젝트의 design 폴더에 저장합니다.

## 모션 패턴

문장·단어·글자 등장, 이미지 마스크, 필터 재배치, 아코디언, 버튼 롤오버 및 포인터 반응은 `MOTION.md`에 정리했습니다. 실제 재생 예제는 `/design-system.html#motion`에서 확인합니다. 속도와 지연은 같은 토큰 원본에 포함됩니다.
